# V8.11.0 Rollback Guide

Rollback applies to a future approved staging/production rollout; none was performed for this local candidate.

1. Revert the frontend to the exact prior V8.10.9 release source (or the deployment's verified prior commit) and restore its matching hosting artifact.
2. In Supabase, drop `trg_hse_status_history` from `public.hse_records`, then drop `public.enforce_hse_status_history()`. Preserve the new `data.update_history`, status actor/time and effective completion fields for audit; older code can ignore these JSON keys.
3. Restore the previous RPC definition only if it was separately changed during the rollout. The V8.11.0 migration itself does not replace `create_hse_record` or `update_hse_record`.
4. Do not delete or rewrite records, attachments, action links or history JSON during rollback.
5. Verify tenant RLS, permits, attachments, CAPA, training, dashboard, imports/exports and action workflows against the prior release.

Always rehearse rollback against the staging clone and retain the original database backup. The prior V8.10.9 ZIP, source snapshot and Git bundle are separate preserved artifacts.
