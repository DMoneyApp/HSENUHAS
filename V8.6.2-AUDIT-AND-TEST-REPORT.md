## Change made in V8.6.2

`app.js`: do not clear `importDraft` after import when one or more rows fail. The draft remains available for correction and retry. Successful rows remain persisted; duplicate detection should skip those records by default on retry. The code does not promise transaction-wide rollback: the import is row-by-row, and successful rows are not automatically rolled back if another row fails.

Added `qa/import-retry-regression.js` and included it in the static smoke check. Updated the V8.6 changelog and QA report.

## Migration safety

`supabase/v8.6-enhancements.sql` is incremental and states that it depends on the existing V8 multi-tenant migration. It modifies notification-state schema/policies, organization-branding Storage policies, and permit authorization RPCs. Review it against the actual live schema before execution. Take a production backup/export first. Do not rerun `v8-multitenant.sql` or `v8.3-hotfix.sql` merely for this release; prior context says those earlier migrations succeeded.

Static inspection of SQL is not proof that the live Storage policies or database functions are correct. In particular, the package's logo upload code change cannot itself prove that the live RLS policy is correct.
