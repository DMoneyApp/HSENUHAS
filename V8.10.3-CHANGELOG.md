# NUHAS HSE360 V8.10.3 — Workflow Completion & Training Matrix

**Package type:** Cumulative local release candidate. The existing Supabase integration is preserved and intentionally not changed during this increment.

## Implemented in V8.10.3

### Role-specific training requirement matrix
- Competency records now distinguish `Employee Evidence` from `Role Requirement` using an explicit record purpose.
- An authorised user can define course code/name, required designation, department, employment scope (`All`, `NUHAS`, `Contractor`, `Other`), strength (`Mandatory` or `Conditional`) and an optional refresh interval.
- Form fields switch between evidence and requirement entry; switching purpose clears the hidden, opposite-purpose data to avoid carrying stale employee/certificate fields into a requirement (and vice versa).
- The matrix matches employee evidence using normalised employee codes and course codes. It does not use names to infer training completion.
- Role/department matching is case/spacing-normalised and supports explicit `All roles` and `All departments` scope labels.
- Duplicate requirement keys and incomplete scope/strength are surfaced as configuration gaps and excluded from automated matrix matching.
- Explicit expiry date takes precedence. If expiry is absent, an expiry can be derived from issue date only when the approved requirement has a valid whole-number refresh interval from 1 to 120 months; end-of-month dates are clamped correctly.
- Mandatory coverage distinguishes valid, due soon, expired, missing evidence, missing employee code and unverified/invalid expiry. Conditional requirements appear in export but are excluded from mandatory-gap counts.
- CSV export includes requirement/evidence references, row status, expiry source and review notes.
- An empty requirement library is not silently treated as non-compliance. The panel says the matrix must be configured from an approved NUHAS training plan.

### Audit and serious-case follow-up
- The audit register now flags report-issued/follow-up/closed audits with findings but no linked corrective action, using source ID or a matching record/action reference.
- A major/critical incident or accident cannot be newly set to Closed unless an actual linked corrective action exists. A typed free-text note by itself does not count as linkage.
- Existing records already marked Closed are not newly blocked solely because they pre-date the rule. This is a frontend workflow gate, not a server-side security rule.

### Waste movement traceability
- Completed Collected / Transferred / Disposed movements now require waste stream, assessed hazard class, positive quantity, unit, disposal/recovery method, movement date, destination, vendor/collector and movement evidence.
- Hazardous movement requires a manifest or collection ticket. Future or invalid movement dates are blocked. Stored-on-site entries require a storage area.
- Incomplete movements may still be saved as Draft while evidence is being confirmed.
- The same traceability preflight is applied to manual form submission and CSV import; an import cannot bypass the frontend checks.
- The quality panel additionally surfaces missing/invalid/future movement dates and missing storage area. Missing transport authorisation remains a human applicability review prompt, not an automatic legal conclusion.

### Preserved cumulative features
- V8.10.2 mobile global search and no-match behavior.
- Recoverable current-tab form drafts, checklist-first fire equipment inspections, JSA reuse, permit review controls, corrective-action work queue/closure checks, compliance renewals, document control/import review, incident/accident workflow fields, register-quality panels and exports.
- Older release notes and source/QA history remain in the master.
