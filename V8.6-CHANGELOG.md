# HSE360 V8.6 — consolidated implementation update

## Implemented in this package

### Reviewed document/data import
- Added a dedicated **Data Import & Extraction** page under navigation.
- Supports CSV; XLSX/XLS through SheetJS; DOCX text extraction through Mammoth; selectable-text PDF extraction through PDF.js; and TXT/MD.
- Provides editable source cells, per-column field mapping, 10 MB / 200-row / 30-column limits, duplicate detection, validation before saving, row-level error export, and explicit confirm-before-import.
- Uses the active organization, create permission and audited `create_hse_record` RPC. Bulk-imported work permits are always saved as `draft`.
- Scanned PDFs/image OCR and AI semantic extraction are not included. PDF/DOCX/TXT content is extracted as text and must be manually mapped/verified.
- Existing module-level CSV import actions now route through the reviewed import workspace instead of immediately writing rows.

### Safety workflow improvements
- Fixed JSA picker persistence by adding a selected-template field to the risk assessment form.
- Expanded the reusable JSA library for EOT cranes/heavy loads, conveyors/rotating equipment, furnaces/upcast areas, circular saws, chemical stores, forklift movement of reels, and mechanical isolation.
- Expanded fire equipment checks with serial/asset number, capacity, service/expiry dates, inspector, follow-up and corrective-action due date fields.
- Frontend permit approval checks now require administrator approval and key class/subtype controls when a permit is moved to `approved`.
- New SQL migration validates permit approvals inside the database RPC as well, records approver identity/time, and writes an `APPROVE` audit action. Incomplete drafts remain allowed.

### Notifications and company branding
- Notification unread counts now reflect unread state and show relevant module badges in navigation.
- Added backend-persisted per-user/per-company notification state (read/dismissed) with browser-local fallback when the optional V8.6 migration is not yet installed.
- Changed unique company-logo uploads to non-upsert uploads, and added an explicit authenticated SELECT policy for organization branding assets so Storage upsert/object checks are less likely to fail.

### Output quality
- Fixed print window creation to avoid using the `noopener` feature string that can yield a null `window.open` handle in some browsers.
- Added setup notes, migration instructions, and import parser smoke tests.

## Requires one manual Supabase migration

After taking a backup, run `supabase/v8.6-enhancements.sql` in the Supabase SQL Editor. It adds the notification state table and RLS policies, adjusts organization branding storage policies, and hardens PTW authorization inside the database RPCs. Do not rerun the older V8 multi-tenant migration or the V8.3 hotfix for this version.

### V8.6.1 hardening
- Import date validation rejects impossible dates (for example 31/02/2026) instead of silently substituting today; blank dates alone default to today.
- CSV parsing rejects unclosed quoted fields.
- Security-definer functions in the incremental V8.6 migration pin an empty search path and schema-qualify application objects.

### V8.6.1 import retry correction
- Preserve the reviewed import draft when one or more rows fail validation or database insertion, allowing corrections and retries without uploading the source file again.
- Successful rows remain in the register and are detected as duplicates on retry (skipped by default); users must review the row-level error report before retrying.
- Added a regression guard for this state transition. This is a local code fix and has not been deployed to GitHub Pages.


### V8.7.0 certificate document assistant (local release candidate)
- Added a dedicated PDF reader for third-party certificates, permits and NOCs in Import & Extract.
- Selectable PDF text is extracted first; image-only/scanned PDFs fall back to Tesseract.js OCR running in the browser (first 10 pages, file limit 10 MB).
- Field suggestions cover document type, certificate/document number, issuer, issue date and expiry/valid-until date. Ambiguous numeric dates are intentionally left blank for human review.
- User must review/edit fields and explicitly save to the existing Licences & Certificates register through the organization-scoped `create_hse_record` RPC.
- No new database migration is required for the metadata fields because the existing licenses record data is JSON-backed.
- Important limitation: this workflow does not upload/retain the original PDF, verify document authenticity, or use a hosted AI service. Browser OCR requires access to the pinned CDN libraries and may require model downloads.
- Added `qa/certificate-reader-smoke.js` for date parsing and extraction heuristic checks.


## V8.8.0 — Linked corrective-action workflow (local release candidate)
- Eligible source records (observations, incidents, near misses, inspections, audits, NCRs, risks, permits and selected operational registers) now offer a permission-checked **Create corrective action** workflow.
- The workflow requires an action description, responsible person and due date, captures priority and an effectiveness-check prompt, and stores the source record ID/reference on the action.
- Source record detail pages show linked corrective actions and allow users to open them directly. Closing/dismissing an action is not treated as closing the source record.
- Added a static regression guard for source linkage, required fields and create permission checks.
- No database migration added; uses the existing audited `create_hse_record` RPC and `actions` module. Live role/RLS and browser testing remain outstanding.
