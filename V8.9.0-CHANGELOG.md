# NUHAS HSE360 V8.9.0 — Reusable JSA and data-quality checkpoint

## Implemented in this local cumulative candidate

- Added company-saved reusable JSA templates using the existing tenant-scoped HSE record RPC and organization access model. A risk assessment can be explicitly marked as a reusable template, given a template name, and saved to the company workspace.
- The JSA picker now combines the built-in activity library with eligible saved company templates, supports searching and selecting multiple activities, and inserts activities, hazards and controls into permit/risk forms for job-specific review.
- Added validation before a record can be saved as a reusable template: template name, activity, hazard and at least one control are required.
- Reusable JSA templates are labelled in the risk register and excluded from operational risk counts, period activity counts and the management overview's operational-risk figures.
- Dashboard metrics now show an em dash where no source records exist for selected-period LTI, exposure hours, training sessions, toolbox talks, near misses or participant-hours, rather than suggesting a measured zero.
- Added regression smoke coverage for JSA template persistence/reuse and retained the previous regression suite.
- Updated product research notes with implementation lessons from SafetyCulture, Intelex and MaintainX: inspection templates and action traceability, permit/JSA linkage and authorization, and mobile-first capture/offline synchronization. Only general UX patterns are adopted; no third-party code or branding is copied.

## Design and safety boundaries

- Built-in and saved JSAs are starting points, not approved site-specific assessments. Users must review hazards, controls, risk ratings and actual site conditions before submission or authorization.
- Saving a template does not approve it and does not authorize work.
- Company-saved templates are stored as tagged records in the existing risk module using the existing record RPC. They are not a new database table. Existing backend authorization and RLS still need live integration testing.
- Existing permits retain Draft-first behavior. Safety-critical validation and approval remain necessary before work is authorized.
- No live database migration, GitHub push or production deployment was performed.

## Release status

Local cumulative candidate only. Not production-ready until live authentication, tenant isolation, Storage policies, permit lifecycle, browser and report/PDF tests pass.
