# NUHAS HSE360 V8.8.9 — Usability and controlled-reporting improvement

Baseline: uploaded `NUHAS-HSE360-V8.8.8-CUMULATIVE-MASTER.zip`.
Status: local cumulative candidate only; no GitHub push, deployment, or production SQL execution.

## Changes in this checkpoint

- Improved active workspace identity with a company logo/name treatment in the application header.
- Added dashboard quick-capture shortcuts for observations, near misses, first aid, permits, JSA/risk assessment, and fire equipment checks.
- Added 1, 3, 6 and 12-month dashboard period presets and period-filtered KPI calculations for the available local record data.
- Added report period presets, register-scoped reporting, document number, revision, issue date, prepared/reviewed/approved-by metadata, and print/PDF output with an explicit uncontrolled-when-printed/approval disclaimer.
- Added optional document-control metadata to records and a printable record layout.
- Added a distinct fire-equipment inspection checklist report layout.
- Added notification unread counts to navigation items/sections, alongside notification actions that dismiss alerts without deleting source records.
- Added a searchable, multi-select JSA starter picker that can insert selected activities, hazards and controls into permit/risk forms. Templates are clearly starters and require job-specific review.
- Made permit entry draft-first and allowed incomplete drafts while retaining validation of permit validity and safety controls before approval.
- Added responsive styling for the workspace selector, quick actions, period controls and form disclosures.
- Added `qa/v889-usability-smoke.js` with 19 static regression guards.

## Known limitations / next work

- Company profile/logo workflow has defensive validation and cleanup handling, but live save behavior remains unverified until Supabase connectivity/authenticated access is available.
- JSA library is a starter library in frontend code, not yet a centrally managed, version-controlled and approval-controlled database library.
- Dashboard KPI accuracy depends on the records and fields currently captured; unrecorded man-hours or incomplete records must not be interpreted as zero risk.
- Report generation is browser print-to-PDF; PDF appearance should be verified in target browsers and the resulting document still requires authorized review/approval.
- Permit workflows and critical-control enforcement need authenticated integration tests against the actual deployed schema before operational use.
- GitHub and live deployment remain unchanged.
