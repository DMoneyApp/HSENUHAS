# V8.11.1 Known Issues and Remaining Work

1. **Record-form integration is pending.** Remove repeated manual document number/revision/issue-date entry from generic forms only after the current document master is resolved by active organisation, document type and effective date.
2. **Historical snapshots are pending.** On record create/issue, store the selected document master ID and snapshot document number, revision and issue date. Existing records must not be rewritten when a master changes.
3. **Effective revision resolver is pending.** For a record event date, select the active master revision whose effective date range covers that date. If no unambiguous revision exists, flag it rather than silently using the newest revision.
4. **Revision lifecycle UI is pending.** Creating a new revision should close the prior revision's effective period and add a new revision row; do not overwrite the only historical master entry.
5. **Document history UI is pending.** The migration stores before/after snapshots, but this candidate has no dedicated history viewer yet.
6. **Reviewer/approver assignment UI is pending.** The schema has reviewer/approver names, but the current row editor does not expose them.
7. **Prefix updates need policy confirmation.** Current prefix save regenerates document numbers for current master entries. Before production, confirm whether a prefix change should create a new revision/history event instead of renumbering existing controlled documents.
8. **Bulk issue-date semantics need approval.** The current action updates issue_date and effective_from for all current master entries. For ISO-controlled documents, consider separate actions for a common initial date versus a new effective revision, and avoid retroactively changing a document's effective date without confirmation.
9. **Seeded starter codes need review.** Some abbreviations are proposed local conventions, not ISO-mandated document identifiers; administrators should be able to customise them.
10. Migration and UI are not staging-verified. Do not deploy or apply to production.
