# NUHAS HSE360 V8.10.6 — Trial Usability & Draft-First Capture

## Goal
Improve the single-company trial experience without touching Supabase configuration, schema, storage policy, production records, or deployment.

## Implemented
- Added an explicit **Save draft** action to the shared record form, so users do not need to remember to change the Status dropdown before saving incomplete information.
- The action sets the record status to `draft` and calls the existing record save pipeline, preserving existing CRUD RPCs, attachment behaviour, record references, and post-save refresh.
- Corrective-action draft records can now be saved without an owner, due date, closure evidence, or effectiveness verification. These requirements still apply when the record is progressed beyond Draft; the existing closure validation remains intact.
- Kept local in-tab draft recovery, permit-specific draft handling, and module-specific validations for non-draft records.
- Added ten dedicated regression assertions.

## Validation
- `node --check app.js`: passed.
- All 40 `qa/*.js` scripts passed, including the 10 new V8.10.6 draft-first checks.
- The ZIP archive integrity and SHA-256 manifest are checked at packaging time.

## Not verified / deferred
- Authenticated browser acceptance tests and real Supabase create/read/update/reopen tests were not run in this environment.
- No Supabase SQL/config/storage changes, GitHub push, or deployment were performed.
- This is a local trial candidate, not a production-ready or ISO/ADOSH-certified system.
