# NUHAS HSE360 V8.8.4 — Certificate duplicate prevention and renewal history

## Implemented in the local cumulative master

- Added a **Previous certificate** selector to the reviewed certificate PDF workflow. It is populated from certificate records visible in the currently loaded active-company register.
- Before uploading a PDF, the browser compares normalized certificate number, issuer and expiry date. When the number is absent, it falls back to normalized document title, issuer and validity dates. A detected match stops the upload and offers to open the existing record.
- Different expiry dates are not considered automatic duplicates when a certificate number and issuer match, so a renewed version can be recorded. The user can explicitly select the predecessor.
- Saved renewals include `renewal_of_record_id`, `renewal_of_reference`, `renewal_record_type` and the existing `related_reference`.
- Certificate record details now show the linked predecessor and successor records, with buttons to open each record. The Licences & Certificates register identifies renewed and superseded records and shows expiry dates. Superseded predecessor records are excluded from renewal alerts so historical certificates do not keep triggering renewal warnings.
- Added `supabase/v8.8.4-certificate-duplicate-guard.sql`, a **candidate** pair of tenant-scoped unique indexes and a preflight check. The migration stops without deleting history if duplicate keys already exist. Distinct expiry dates remain permitted for renewal.
- Added deterministic tests for normalization, exact duplicate matching, different issuers, missing certificate numbers, predecessor/successor relationships, superseded-alert behavior, and static SQL safeguards. V8.8.5 extends expiry-alert windows and status handling; see `V8.8.5-CHANGELOG.md`.

## Limitations

- The initial duplicate warning runs against records currently loaded in the active-company register and is not a guarantee against concurrent or direct API submissions by itself. The SQL unique indexes are intended to provide the server-side duplicate boundary after staging verification and application.
- The SQL migration may intentionally fail its preflight when existing duplicate rows are found. Investigate records and confirm the correct historical record with the business owner before applying; never delete history automatically.
- No GitHub push or production database change was performed.
