# V8.11.0 Known Issues and Limits

- The controlled reference workbooks, near-miss form and tracker screenshot named in the request were not accessible. Current repo fields were preserved and supplemented; final field mapping requires the approved originals.
- The status-history migration is a candidate and has not been applied or exercised against Supabase. Schema drift, existing triggers and deployed RPC versions must be reviewed in staging.
- Browser layout, real role permissions, database write failures, and app reload persistence were not exercised interactively without an authenticated staging environment.
- Operational tables use a compact horizontally scrollable table on narrow displays. Confirm legibility on actual supported phones during browser QA.
- Register counts exclude Draft rows and include saved records under current search/date/department/quality filters. Status chips show counts across all statuses while honoring those other filters.
- Closed case policy is strict: cases cannot close with outstanding linked actions; major/critical cases need at least one linked action. No override workflow was added because no approved override role/reason/approval rule was provided.
- History is protected against edits through the supported RPC/trigger path; database owners with direct administrative access can still alter data. Treat administrative database access as privileged.
