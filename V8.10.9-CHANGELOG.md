# NUHAS HSE360 V8.10.9 — Cumulative HSE360 & Attachment Persistence Fix

**Release type:** local cumulative release candidate, based on the repository's V8.10.8 source checkpoint.
**Date:** 17 October 2026.
**Deployment:** not pushed or deployed. The live Pages endpoint was observed serving V8.10.8.

## Fixed

- Updated the audited `update_hse_record` RPC so an omitted or `NULL` `p_attachment` retains the record's current attachment metadata. Previously, a valid edit RPC call could clear the attachment pointer without uploading a replacement.
- Added `supabase/v8.10.9-attachment-preservation.sql` for installations that already have the V8 tenant schema. It retains existing edit authorization, audit logging, permit validation behavior, and a pinned `search_path`.
- Updated the corresponding RPC definitions in the base tenant migration and V8.6 enhancement SQL so new installations and cumulative source agree.
- Added `qa/v8109-attachment-preservation.js` to catch regression in the migration, base schema and enhancement schema.

## Carried forward

All V8.10.8 cumulative application source, auth integration, existing modules, data imports/exports, local drafts, JSA starter/template selection, permit UI workflow, QA scripts, and prior release notes remain included.

## Limits

- The permit workflow is still not a server-enforced issuer → receiver → HSE identity workflow. The existing UI checks profile display names; the candidate lifecycle SQL does not establish the full approval chain or rejection/return/cancellation audit workflow.
- The migration is not applied. The live Supabase schema, RLS, permissions, and storage policy remain unverified.
- Existing SQL migrations and report/print output were not executed in a live database/browser.
- No files were removed. This is not a production-ready or legally validated authorization system.

See the V8.10.9 QA, audit, pending-work, deployment, and rollback documents for evidence and release boundaries.
