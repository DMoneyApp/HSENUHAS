# V8.7.0 — Certificate / Permit / NOC Reader

## What it does

- Accepts PDF files up to 10 MB.
- Extracts selectable text using PDF.js; if little/no text is present, renders up to 10 pages and runs Tesseract.js OCR locally in the browser (English model).
- Suggests document type, document/certificate number, issuer, issue date and expiry/valid-until date.
- Shows extracted text for reference and lets the user correct the suggested fields.
- Saves only after explicit confirmation, to the active company's Licences & Certificates register via the existing authenticated `create_hse_record` RPC.
- Records the source filename and a limited text excerpt in the record metadata; it does not store the PDF bytes.

## How to use

1. Deploy the frontend files as described in `V8.6-DEPLOYMENT-CHECKLIST.md`.
2. Sign in and choose the intended company workspace.
3. Open Import & Extract and scroll to Read a certificate, permit or NOC.
4. Select a PDF. Wait for extraction/OCR.
5. Compare each field with the original document. Enter missing or uncertain values manually.
6. Save the reviewed certificate. Verify the new record in Licences & Certificates.

## Important limits

- OCR output can be wrong, especially for low-resolution scans, stamps, handwriting, tables and multilingual documents. The user must verify every field.
- Ambiguous numeric dates such as `05/06/2026` are intentionally not auto-converted. Enter the date after checking the document's date convention.
- English OCR only; OCR model/library loading requires access to the pinned public CDN.
- The PDF is processed in the browser and is not uploaded or retained. Evidence storage/attachment integration is not part of this slice.
- No AI model training or cross-company memory learning is performed. The code uses deterministic field-label heuristics over extracted text. A future hosted AI service would require an approved provider, server-side secret management, data-handling review and cost/retention decisions.
- No certificate authenticity check, approval or renewal notification is implied by extraction or saving.

## Later implementation addendum — V8.8.3 local candidate

The original V8.7 behavior described above saved metadata only. In the V8.8.3 cumulative candidate, after extraction and human review, the original PDF is uploaded to the existing private `hse-attachments` bucket and the attachment metadata is linked to the new certificate record. A failed record creation triggers best-effort deletion of the uploaded object; if cleanup cannot be confirmed, the UI displays a warning. This update is verified by local deterministic/static QA only. Test upload, signed URL download, RLS/Storage tenant isolation, and failure cleanup in a non-production Supabase environment before production use.


## V8.8.4 local candidate addendum — duplicate detection and renewal chain
Before PDF upload, the reader checks loaded Licences & Certificates records for normalized duplicate number/issuer/expiry keys. If a number is missing, it falls back to title/issuer/validity. Users may select a predecessor; its id/reference are saved, and record detail views link predecessor and successor certificates. Distinct expiry dates are allowed to represent renewal. `supabase/v8.8.4-certificate-duplicate-guard.sql` adds candidate tenant-scoped unique indexes after preflight checks; it has not been executed in Supabase and must be rehearsed in staging first. See `V8.8.4-CHANGELOG.md` and `V8.8.4-LOCAL-QA-REPORT.md`.
