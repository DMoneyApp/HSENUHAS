# NUHAS HSE360 V8.10.8 — Permit Workflow & Approval Inbox Checkpoint

**Purpose:** This document describes the frozen source rollback point created immediately before the requested simplification of reporting screens and controlled printouts. The V8.10.9 audit could not locate the original ZIP referenced by historical notes; keep this checkpoint and source history intact.

## Cumulative baseline

V8.10.8 continues from the full V8.10.7 cumulative master. It preserves all previous modules, CSS, Supabase integration files (unchanged), starter JSA library, inspection checklists, registers, dashboards, notification handling, imports, report exports, document-control fields, regression tests, historical changelogs, implementation notes, and continuation checkpoints.

## Added in the V8.10.8 working increment

1. **Staged permit workflow in the frontend:** explicit Submit, receiver acceptance, HSE authorisation and work-close actions. Drafts can remain incomplete; active permit stages are not intended to be changed by directly editing a status dropdown.
2. **Assignment-aware permit actions:** the trial UI can assign the issuer/requestor, receiving department representative and HSE reviewer by profile/name, and checks the current profile name against the assigned person before allowing the relevant stage transition.
3. **Permit safety preflight:** permit submission checks the work scope and validity window; HSE authorisation checks documented risk/JSA references, hazards, controls, distinct named signers and additional task-specific safety fields for hot work and critical-work subtypes.
4. **Dashboard approval inbox:** permits awaiting receiver acceptance or HSE authorisation can appear as actionable items for the matched profile. The dashboard and notifications use the shared assigned-task calculation.
5. **Company profile/logo save resilience:** reject blank company names, validate logo type/size before upload, recover the save button after returned/thrown errors, preserve the previous logo on failure, and attempt cleanup of an uploaded but unlinked image.
6. **Direct CSV import recovery:** undated rows are not silently assigned today's date; the operator must explicitly approve date fallback or the affected rows are skipped and included in a downloadable row-level error CSV. Invalid dates and row save/network failures are reported rather than hidden.
7. **Regression tests:** five V8.10.8-specific checks cover permit approval wiring, CSV import recovery, dashboard approval inbox, company-profile resilience and runtime permit transition helper behavior.

The new printable register layouts and changes to simplify the record screens are **not included** in this baseline. The historically referenced ZIP is unavailable in the accessible repository/release history.

- It has not been confirmed in an authenticated browser session against the live backend. The local QA pass does not prove the workflow is live-ready.
- No Supabase SQL, configuration, storage policy, production records, GitHub repository, or deployed website was changed.

## How to roll back

1. Preserve this checkpoint and the commit/source snapshot that identifies V8.10.8.
2. Locate the original V8.10.8 ZIP from a trusted external archive and verify its original SHA-256 before using it.
