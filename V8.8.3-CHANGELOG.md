# NUHAS HSE360 V8.8.3 — Certificate source-PDF retention

## Implemented locally

- After PDF extraction and human review, the certificate reader uploads the original selected PDF to the existing private `hse-attachments` bucket.
- Storage path follows the existing multi-tenant layout: `{organization_id}/{user_id}/{uuid}-{sanitized_filename}`.
- The uploaded attachment metadata (`path`, original `name`, `size`, and `application/pdf` type) is linked to the new Licences & Certificates record using the audited `create_hse_record` RPC `p_attachment` parameter.
- The reader validates that a non-empty PDF no larger than 10 MB is selected, and revalidates the source file at save time.
- If record creation fails after upload, the client attempts to remove the just-uploaded object. If cleanup cannot be confirmed, an explicit message warns that an orphaned file may need administrator review.
- If the record succeeds but the list refresh fails, the UI correctly reports that the record was saved rather than falsely implying that save failed.
- The source PDF is released from in-memory state after a successful save.
- Expiring within 60 days is labelled `Due for Renewal` rather than `Partially Compliant`.
- Added `qa/certificate-attachment-workflow.js` with deterministic file validation/path tests and static wiring assertions.
