# NUHAS HSE360 V8.10.7 — Network Failure Recovery

## Context
Continuation after an interrupted work session, based on the V8.10.6 cumulative master. This increment focuses on keeping record forms usable when a network call rejects or throws unexpectedly. Supabase configuration, SQL, storage policies, and production data were not changed.

## Changes
- Wrapped record attachment upload and create/update RPC operations in a failure-recovery boundary.
- On a thrown error or returned RPC error, restore the save button, keep the form open, and show a retry-oriented error message.
- Attempt cleanup of a newly uploaded attachment when record persistence fails, and disclose when cleanup itself cannot be confirmed.
- Preserve the existing attachment when editing a record without selecting a replacement.
- Ensure record loading always clears its loading state after returned errors or thrown connection failures.
- Guard auth session bootstrap and auth-state transitions so thrown network errors return a useful sign-in message instead of leaving the page stuck.
- Added targeted static regression coverage in `qa/v8107-network-resilience-smoke.js`.

## Limitations
- These are local source-level resilience checks, not proof of a live Supabase outage/recovery test.
- Browser end-to-end testing remains blocked/unverified in this environment.
- No SQL, Supabase configuration, production data, GitHub, or deployment changes were made.
