# NUHAS HSE360 V8.10.4 — Workflow Quality & Safe CSV Export

## New in this increment
- Hardened the shared CSV cell encoder against spreadsheet formula injection in user-controlled values.
- Values beginning with spreadsheet formula operators (`=`, `+`, `@`, and non-numeric `-`) are prefixed with a text marker before CSV quoting. Leading whitespace/control characters are considered when checking for formula-like values.
- Ordinary negative numeric values remain numeric text (for example, `-125.50`) instead of being unnecessarily altered.
- Because the shared encoder is used by register, report, audit, training, competency, renewal, and import-error CSV exports, the protection applies consistently across those export paths.
- Added `qa/csv-export-injection-smoke.js` with eight deterministic assertions for formulas, whitespace-prefixed formulas, negative numbers, blanks, and quote escaping.

## Carried forward
All V8.10.3 workflow completion improvements and the full cumulative source/QA/documentation history remain included.

## Boundaries
- This is client-side CSV export hardening, not a replacement for safe spreadsheet import policies or backend validation.
- No Supabase configuration, SQL, RLS, storage, RPC, or production data was changed.
- No GitHub push or deployment occurred.
- Authenticated browser E2E and live integration remain unverified.
