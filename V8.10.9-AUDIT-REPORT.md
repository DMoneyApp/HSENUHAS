## Defect reproduced and repaired

The V8 database `update_hse_record` RPC wrote `attachment=p_attachment` even though the parameter defaults to NULL. A valid RPC call that omitted attachment metadata therefore replaced existing attachment metadata with NULL. The frontend normally resends its loaded attachment, but RPC callers are not required to do that. V8.10.9 now uses `coalesce(p_attachment,r.attachment)` in the base schema, enhancement schema and a forward migration. Regression coverage checks all three SQL paths and verifies the migration retains authorization/audit/permit checks.

Architectural decision: retain the existing HTML/JavaScript + Supabase RPC architecture. `NULL` means “no replacement supplied” because the current client has no attachment-removal workflow. The SQL uses the current target row value in the UPDATE expression so preserving metadata does not rely on a potentially stale pre-update read. Removal semantics are intentionally not added without an explicit product workflow.
