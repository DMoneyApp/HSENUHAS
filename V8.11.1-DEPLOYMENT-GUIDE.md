# V8.11.1 Staging Guide

This is a development candidate only. Do not publish it to GitHub Pages or apply its migration to production.

1. Create/export a backup of the staging Supabase database.
2. Confirm the staging schema has `public.organizations`, `public.is_org_member(uuid,uuid)`, and `public.is_org_admin(uuid,uuid)`.
3. Review `supabase/v8.11.1-document-master.sql` with the database owner.
4. Apply the migration to staging only.
5. Deploy the development branch to a separate preview, not the production GitHub Pages branch.
6. Sign in as an active organisation administrator. Open Document Master Register and verify initial seed.
7. Test a second organisation using a different prefix. Confirm no document rows or settings leak across organisations.
8. Sign in as a non-admin and confirm read-only access and that missing configuration does not trigger an insert attempt.
9. Test bulk issue date, individual row edits, number-format changes, custom entries, CSV export and history snapshots.
10. Do not treat this candidate as complete until record-form integration, print output and per-record historical snapshots are implemented and tested.
