# NUHAS HSE360 V8.10.9 — Pending Work and Known Issues

This local candidate is not production-ready. The following gates remain open:

1. **Permit security/workflow:** implement backend-verified issuer, receiver, HSE and department-head assignment using immutable user IDs; enforce stage order in a database transaction; record append-only approval actions; add return-for-correction, rejection, cancellation, expiry, suspension/resumption and closure rules. Verify role authorization and concurrency. Names and typed sign-offs in the current UI are not cryptographic signatures.
2. **Database staging:** reconcile schema and migration history; apply the V8.10.9 attachment migration to a disposable/staging Supabase instance; verify existing and replacement attachments, authorization-denied paths, audited event, permit behavior, and rollback. No SQL runtime was available in this run.
3. **Live integration:** test login/logout, registration, recovery, forced password change, organization access approval, two-tenant isolation, RLS, RPC permission denial, private Storage access and admin password reset with authorized test accounts.
4. **Browser acceptance:** authenticated desktop/mobile create, draft, edit, view and submit flows across high-priority forms; JSA association; CAPA closure; filters; PDF print pagination; CSV/XLSX import/export and failure recovery. Local source tests do not prove these interactions.
5. **Operations:** configure and verify background renewal reminders if required; currently notices are computed while the application is open. Confirm KPI definitions, audit criteria, applicable ADOSH and local requirements with NUHAS HSE/legal owners; this release does not invent or certify them.
6. **Rollback artifact:** locate the authentic V8.10.8 rollback ZIP and verify it against its original SHA-256 if one exists outside GitHub. Repository, Git tree, GitHub Releases and root assets did not contain it. The pre-change Git bundle and source snapshot are verified preservation copies, not a substitute represented as the original archive.
7. **Release authorization:** review and approve the staged migration; then separately authorize any GitHub push, Pages deployment or production migration. None was performed here.

## Known UX / technical limitations

- JSA starter content needs site-specific competent review and is not an approved risk assessment.
- Local recoverable form drafts use tab session storage; they are not encrypted authoritative records, do not include attachments and do not sync across devices.
- PDF/OCR extraction is assistive and requires review against originals; external CDN availability is required.
- Candidate SQL guards under `supabase/` have not been executed on the production database.
- The original V8.10.8 ZIP is missing from the accessible release history; do not claim the authentic ZIP rollback archive was preserved or verified.
