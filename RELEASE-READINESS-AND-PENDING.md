## V8.8.6 certificate importer update

Selectable PDF text is reconstructed by visual line position. Low-quality text can trigger browser OCR, low-confidence scans of up to three pages receive an alternate layout pass, and issuer/recipient suggestions are filtered for likely OCR noise. A distinct holder/recipient field is saved in record JSON. For UAE workflows, ambiguous numeric dates use day-first interpretation, and the review notice explicitly requires checking dates against the original. The source PDF from the reported screenshot was not available for a direct OCR run, so this is improved local logic—not proof that every scan will parse correctly. See `V8.8.6-CHANGELOG.md` and `V8.8.6-LOCAL-QA-REPORT.md`.

## V8.8.5 renewal reminder behavior

In-app renewal notifications are raised at 90/60/30/7-day bands, on the expiry date, and while overdue. Invalid nonblank expiry values are surfaced for correction. Alerts are generated by the open application rather than a scheduled background job; outgoing email and push delivery remain unimplemented/unverified. See `V8.8.5-CHANGELOG.md` and `V8.8.5-LOCAL-QA-REPORT.md`.

## V8.8.4 certificate duplicate / renewal details

The reader checks the currently loaded license records before uploading and can link a newly issued certificate to a predecessor. A candidate migration adds organization-scoped unique indexes and a duplicate preflight. Certificate predecessors with recorded successors are omitted from renewal alerts; the latest successor remains eligible for expiry tracking. Because the migration will stop when legacy duplicates are found, review and reconcile them with the certificate owner before attempting it. Do not delete historical records solely to make the migration pass. See `V8.8.4-CHANGELOG.md` and `V8.8.4-LOCAL-QA-REPORT.md`.

## Mandatory work before production use

1. **Database/migration verification:** backup the target database; compare its actual schema and applied migration history with this package; run the candidate V8.8.1/V8.8.2/V8.8.4 migrations first in a non-production Supabase project, after reviewing each migration and its preflight results. Execute and test all state transitions, error paths, old-record edits, concurrent duplicate action submissions and audit logging. Do not blindly run migrations against production.
2. **Tenant isolation/RLS:** test with two independent organizations and users, including direct PostgREST/RPC requests, not only the UI. Confirm each company's records, profiles, audit events, attachments and exports are inaccessible to non-members.
3. **Authenticated end-to-end browser test:** test sign-in, registration, access requests/approval, record CRUD, inspections, linked actions, closure checks, permits, import retry, certificate parsing/save, upload/download, company switching and mobile layout. The attempted headless Chromium test timed out, so browser E2E is not counted as passed.
4. **Storage security:** the reader now uploads its original PDF to the existing private bucket and links it to the certificate record. Still verify the actual deployed bucket, exact folder policies, owner/tenant authorization, signed-URL scope and real cleanup behavior after failed record creation.
5. **Admin password reset function:** deploy and test `supabase/functions/admin-reset/index.ts` in staging with function secrets stored only in Supabase; verify organization scoping and forced password change. Never put the service-role key in frontend code or GitHub.
6. **Release reconciliation:** compare this source with GitHub `main` and current Pages files before any replacement. This workspace has not pushed to GitHub or applied any production migrations.
7. **Operational sign-off:** test backup/restore, error handling, role permissions, browser/device compatibility, real report output and critical HSE workflows with NUHAS test users. Obtain HSE and IT approval before authorizing use for operational permits or statutory compliance decisions.

## Known limitations

- OCR is browser-side assistance; user review against the original document remains mandatory. CDN libraries require network access, and OCR/date recognition can fail. V8.8.6 adds layout reconstruction, an OCR confidence indicator, fallback scoring and issuer/recipient validation, but the exact user PDF has not been available for direct OCR testing. V8.8.3 source-PDF upload and V8.8.4 duplicate/renewal checks are implemented in source but have not been authenticated against live Supabase storage or a live database. The V8.8.4 duplicate warning checks loaded client-side records; only a successfully tested/applied server-side guard can address concurrent submissions.
- The action closure gate and permit lifecycle triggers are candidate implementations until executed and proven on the target schema in staging.
- Scheduled reminders and outgoing email delivery are not claimed as verified background services.
- A user-interface rule by itself is not a security boundary. Production assurance depends on database permissions, RLS, RPC behavior and trigger execution.
- The application helps manage HSE/IMS evidence; it does not itself certify compliance with ISO 9001/14001/45001/50001 or UAE/ADOSH requirements.

## Why this is not marked production-final

Production readiness depends on testing against the actual Supabase schema, storage policies, authentication configuration and deployed browser application. Those systems were not accessed or changed during this local packaging step. A static pass can show that source checks pass; it cannot prove that a migration compiles on the live database or that cross-company access is blocked in runtime.
