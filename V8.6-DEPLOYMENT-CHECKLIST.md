# HSE360 V8.6.1 Deployment Checklist

## What this package can and cannot prove

This package was built from the V8.5 source archive currently available to the coding session. The environment could not access GitHub or the deployed website, so it could not confirm that these files exactly match the live `main` branch. No changes were pushed to GitHub and no SQL was run against the live Supabase project.

## 1. Back up and review the incremental SQL migration

1. Export/back up the current Supabase database before changing it.
2. Open the existing Supabase project `osdejubbnjmzamizieyd` → SQL Editor.
3. Review `supabase/v8.6-enhancements.sql`.
4. Run it once only after confirming the live schema matches the expected V8 base schema. It does not delete HSE records and does not replace the V8 base migration.
5. Confirm it finishes without error. The frontend intentionally keeps browser-local notification state if this migration has not been applied, but server-side PTW approval enforcement and cross-device notifications require it.

This migration alters database function definitions and Storage policies. Review the SQL against the currently deployed schema before applying if the live database has diverged from V8.5. The security-definer functions in this migration use an empty search path and schema-qualified application objects.

## 2. Update GitHub Pages

In `DMoneyApp/HSENUHAS`, compare the current `main` branch files with this package before replacing anything. Keep the existing `config.js` because it contains your current Supabase URL and publishable key.

Files to update/add:
- Replace `app.js`, `styles.css`, `index.html`, `VERSION.txt`, and applicable documentation.
- Add `supabase/v8.6-enhancements.sql` and `qa/import-parser-smoke.js` if you keep project QA files in the repository.
- Preserve the existing `manifest.webmanifest`, `assets/nuhas-logo.jpg`, V8 SQL migrations and Edge Function unless you have separately reviewed changes to them.
- Do not commit any service-role key or privileged secret.

Commit to the appropriate branch and let GitHub Pages deploy. After deployment, use a hard refresh (Ctrl+Shift+R) on desktop or clear the site cache if the old JS remains loaded.

## 3. Manual acceptance test

### Authentication and tenancy
- Sign in with the existing administrator account.
- Confirm NUHAS logo and workspace name show correctly.
- Confirm a second company workspace (if one exists) displays only its own data.
- Confirm a non-admin cannot edit company identity or approve a permit.

### Import
- Download the template and import a two-row CSV into a test module.
- Confirm the rows appear in an editable review table before any record is created.
- Change one cell and mapping; confirm saved data uses the corrected value.
- Try an exact duplicate; confirm it is skipped unless duplicate override is deliberately selected.
- Import a small XLSX, DOCX and text-based PDF; verify extracted values manually.
- Try a scanned PDF; confirm the app says OCR is not configured rather than silently importing blank text.
- Verify row-level failure CSV and ensure HSE records remain unchanged for failed rows.
- Do not test with unreviewed real employee or sensitive records.

### Permits
- Save an incomplete permit as `draft`.
- As non-admin, attempt to set status to `approved`; it must be blocked in the UI and database RPC.
- As an authorized organization admin, complete required controls and approve a future-valid permit; confirm approver identity/time are stored and `APPROVE` appears in the audit trail.
- Try missing gas-test or isolation fields for a critical permit; approval must fail.

### Notifications and branding
- Mark one alert read and confirm the unread count changes.
- After migration, sign in on another browser/device and verify notification read/dismiss state persists.
- Upload a small JPEG/PNG company logo and save company profile; confirm it displays after refresh.
- Confirm non-admin users cannot upload/replace/delete company branding.

### Reports and responsiveness
- Generate a period report and use Print → Save as PDF.
- Verify company name/logo, report number, revision, issue date, period and prepared-by metadata.
- Test on phone widths and desktop; especially check the import table's horizontal scrolling.

## Rollback principle

Do not rerun the V7/V8 base migration as a rollback. If the incremental SQL causes an issue, stop using the new approval/state features and restore/reconcile from your reviewed database backup with your database administrator. Reverting frontend files does not automatically reverse SQL function changes.

## V8.7.0 certificate reader release notes

V8.7.0 adds a browser-side PDF certificate/permit/NOC reader. It requires the added Tesseract.js CDN script in `index.html`; selectable text uses PDF.js and scanned PDFs fall back to English OCR for up to 10 pages. The user must review the extracted fields and explicitly save them to Licences & Certificates. The PDF itself is not uploaded. No SQL migration is required for this feature alone.
