# V8.11.1 — Organisation Document Control

Status: development branch only. Not deployed and migration not applied.

## Scope
- Adds an organisation-specific document-control settings table and document master table.
- Uses RLS and existing `is_org_member` / `is_org_admin` helpers to isolate tenants and limit changes to active organisation admins.
- Logs prior master-row snapshots on insert/update/delete to a history table.
- Adds a Document Master Register screen with a standard starter library, prefix/number-format defaults, revision/issue date fields, bulk issue-date update, custom document entry and CSV export.
- NUHAS organisations default to prefix ENCF; other organisations default to ORG until their administrator configures their prefix.

## Important limits in this candidate
- The screen manages current master metadata. Existing generic record forms and printed reports are not yet fully wired to select effective document revisions and persist a per-record document-control snapshot. That is the next required integration before treating this as complete.
- The current bulk issue-date action updates the current master entries; the history trigger preserves the prior master values. It does not rewrite existing HSE records.
- The current row editor supports name, number, revision, issue date, effective date and active state. Full reviewer/approver assignment and a dedicated history viewer remain follow-up UI work.
- Browser authentication, role/RLS checks, two-tenant isolation and SQL execution have not been tested against staging.

## Staging steps
1. Export/backup the staging database.
2. Confirm the existing `public.organizations`, `public.is_org_member(uuid,uuid)` and `public.is_org_admin(uuid,uuid)` objects match the existing V8 schema.
3. Apply `supabase/v8.11.1-document-master.sql` in staging only.
4. Sign in as an organisation admin and open Document Master Register; confirm it seeds templates only for the active organisation.
5. Sign in as a non-admin and verify read-only access; test a second organisation with a different prefix.
6. Test prefix change, bulk issue-date change, individual revision changes, history rows and CSV export.
7. Do not apply to production until these tests and record-print snapshot integration are complete.
